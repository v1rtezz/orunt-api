# n8n: лента заказов Orunt через HTTP Request

Описание на словах, без готового workflow-файла: названия полей в интерфейсе n8n могут отличаться между версиями.

## Схема

Лента работает через long-poll: запрос висит до 50 секунд и возвращается сразу, когда появился новый заказ. Поэтому постоянный цикл в n8n строится так: узел HTTP Request, затем обработка заказов, затем сохранение курсора, затем снова HTTP Request.

## Шаги

1. Ключ. Выпустите его в боте @oruntbot: Настройки → API. Создайте в n8n учётные данные типа Header Auth: имя заголовка `Authorization`, значение `Bearer orunt_...` (ваш ключ). Не вставляйте ключ в URL.
2. Узел HTTP Request, метод GET, адрес `https://orunt.pro/api/v1/me/orders`.
3. Параметры запроса: `wait` = `50`, `limit` = `100` (допустимо 1–100), `since` = курсор из прошлого ответа. При первом запуске `since` не передаётся.
4. В настройках узла поставьте таймаут больше 50 секунд, например 70 000 мс. Иначе n8n оборвёт запрос раньше сервера.
5. Ответ — JSON с полями `orders` (массив), `next_cursor` и `has_more`. Разверните массив `orders` узлом Split Out (или Item Lists в старых версиях): каждый заказ станет отдельным элементом. Дальше подключайте любые узлы: Telegram, Google Sheets, Notion, база данных.
6. Курсор. Сохраняйте `next_cursor` после обработки заказов (например, в Workflow Static Data через узел Code, во внешней таблице или базе) и подставляйте его в `since` следующего запроса. Тогда заказы не теряются и не приходят дважды, даже после перезапуска workflow. Курсор приходит и в пустом ответе.
7. Если `has_more` равно `true`, повторите запрос сразу.

## Устойчивость

- Держите один цикл на ключ. Второй одновременный long-poll получит `409 poll_in_progress` с заголовком `Retry-After`. Не запускайте тот же workflow параллельно и не используйте тот же ключ в другом клиенте одновременно.
- При `409` и `429` ждите столько секунд, сколько указано в `Retry-After`.
- При `502`, `503`, `504` сервер обновляется (обычно 10–30 секунд): повторяйте с паузами 5, 10, 20, 60 секунд, курсор не сбрасывайте.
- `401` (ключ неверный или отозван) и `403 plan_required` (нет PRO) повторять бессмысленно: остановите workflow.
- Лимит: 60 запросов в минуту на ключ.

Не передавайте ключ и заказы другим людям: см. условия использования в корневом [README](../../README.md).
